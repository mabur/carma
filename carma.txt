MEMORY MANAGEMENT

* Memory safety problems
  - Dereference uninitialized pointer
  - Dereference null pointer
  - Dereference index out of bounds
  - Dereference old dangling pointer after realloc
  - Dereference old dangling pointer after free
  - Dereference old dangling pointer to shared buffer
  - Dereference old dangling pointer to stack
  - Memory leak
* Memory safety solutions:
  - Always initialize variables solves uninitialized pointer problem.
  - Array iteration macros solve indexing out of bounds and null pointer problems for arrays.
  - Fixed capacity arrays on stack, like small strings.
    - Solves all problems except indexing out of bounds.
    - Adds copying cost for large arrays.
  - Fixed capacity arrays on heap. Never realloc.
    - Solves dangling pointers after realloc, since we never realloc
  - Never free, or just free at the end of the program
    - Solves dangling pointers after free
  - Re-usable shared static array within function
    - Solves memory leak, forgetting to free inside the function
    - Solves dangling pointers after free
    - Adds dangling pointer to shared buffer
* Memory handling
  - Most memory can be allocated on the stack. Also small arrays and strings.
  - Some memory can be allocated once and freed when the program exits, manually or automatically.
  - Some memory can be allocated once and then grow/append as needed during run-time, and then freed when the program exits.
  - Some memory can be allocated as static variable inside function, and shared for all calls to the functions, and freed when the program exits.
  - Some memory can be allocated for a game interval, like a frame or a scene, and then deallocated/cleared after that frame or scene.
  - Some memory can be allocated on the stack using alloca (C&C++) or VLA (C). At least arrays up to ~1000 primitives.
  - What common cases are left?
* Reference counting
* Additional Run-time Memory Safety
  - Prevent dangling pointers and use after free or realloc
  - Have fat pointers and extra layer of indirection to track free and realloc

int main() {
  StringBuilder owner = {};
  APPEND(owner, 'a';
  StringView view = AS_STRING_VIEW(owner);
  PRINT(view); // ok
  APPEND(owner, 'b')
  PRINT(view); // Use after realloc
  FREE_DARRAY(owner);
  PRINT(view); // Use after free
}

* DEFER and MOVE macros, with linter rules to prevent memory leaks and use after free:
  - An owner can be initialized from a SOURCE, or MOVED from another owner.
  - Returning an owner requires MOVE
  - An owner can be assigned and updated with INOUT functions.
  - Solves: no-memory leaks, no usage before init for owners, no use after free for owners. Similar to C++ RAII.
  - Does not solve: dangling pointers for non-owners.
* Allocators, or "never-free-policy" for realloc, to prevent dangling pointers.
* Fixed capacity for all/most arrays, to avoid realloc.
* Allocate on startup, to prevent dangling pointers.
